# 空を歩く、光を編む

雨上がりのアスファルトに落ちた空を、そのまま生きた空にするアプリ。

水たまりの部分だけを参考写真からくり抜き、その中で
[`amanesf/sakura`](https://github.com/amanesf/sakura) の大気散乱と雲のエンジンを
**上向きに**走らせて、水面越しに映す。写真の中で動くのは水たまりだけ。
触れば波紋が走り、映っている空がゆがみ、傾いた面が太陽を拾って光る。

- **空を歩く** — 画面（水面）を押すと波紋が生まれる。水面に何かが描かれるのではなく、
  波の傾きが**映っている空をずらす**。鏡に触れたとき起きてよいことは、
  映っているものが動くことだけ。
- **光を編む** — その同じ傾きが太陽を返す。だから静かな水は光らず、
  一歩踏めば光がほどけ、雨が降れば水面いっぱいに光が編まれる。

## 走らせる

```sh
cd app && npm install && npm run dev
```

写真がなくても動く。アセットが無いときは水面を自前で切り出すので
（`app/src/effects/puddleShader.ts` の FALLBACK）、空・雲・波紋・光はすべてそのまま見られる。
写真は「その街」にするためのものであって、動かすためのものではない。

## 写真とマスク

参考写真と、その水面をマゼンタ (255,0,255) で塗りつぶしたマスクの2枚を渡す:

```sh
node scripts/puddle.js reference.png mask.png
# -> app/public/ref.webp, app/public/mask.webp
# キーの被覆率と最上行を測って、WATER_HORIZON_ROW の値を出力する
```

マスクを**アルファではなく別画像**にしているのは、水面の上に乗っているもの
（電線・電柱・映り込んだ家・少女）を生きた反射の上に残すため。同じ画素について
「写真の色」と「水かどうか」の両方が要るので、RGBA 1枚には入らない。
逆に言うと、マスクは画像編集ソフトで水面をベタ塗りするだけでよく、
電線は塗り残せばそのまま残る。マゼンタは輝度ではなく**色距離**で判定するので、
マゼンタの上に描かれた暗い電線と、空を映した暗い水面を取り違えない。

## 撮る

`sakura` の測定ループをそのまま持ってきてある（`scripts/README.md` はあちら）。

```sh
node scripts/capture.js /tmp/shot.png 0                 # 1408x768 の決定論的キャプチャ
node scripts/capture.js /tmp/shot.png 0 "rain=0.65&hour=17.6"
node scripts/press.js  /tmp/press.png 1.1 0.5 0.5       # 1.1秒前に生まれた波紋を1枚
```

`press.js` は波紋の誕生時刻を**遡らせて**打つ。波紋の実体は「今 − 生まれた時刻」なので、
`?t=` で時間を止めた画面では、そうしないと波紋は生まれていないか無限に古いかのどちらかになり、
このアプリの名前になっている当のものだけが静止画に写らない。

## 構成

| ファイル | 役割 |
|---|---|
| `app/src/scene/puddle.ts` | 水たまりの幾何 — 消失線、カメラの仰角、地面のスケール |
| `app/src/effects/puddleShader.ts` | 水そのもの。キー抜き・反射・波・きらめき |
| `app/src/scene/ripples.ts` | 押された波紋の表（雨の波紋はシェーダ側の手続き生成） |
| `app/src/scene/`, `app/src/core/` | sakura の空・雲・大気・ポストチェーン（ほぼそのまま） |

`sakura` から変えたのは構造的にはひとつだけ:
カメラを**ほぼ真上**に向けてある（`CAMERA_HORIZON_FRACTION = 0.98`）。
描かれるフレームはもう「風景」ではなく、水たまりが映している半球そのもので、
水面シェーダはそれを消失線から手前へ向かって読み下す。
窓のアプリで空が窓枠の向こうにあったのと同じ意味で、ここでは空は足元にある。
